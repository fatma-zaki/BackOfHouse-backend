# Database Design Rules

> Project-wide conventions for the `app` schema. PRD basis: §14.1 (non-sequential public ids, UTC, soft delete with retention, creator/modifier for sensitive entities, separation of sensitive data, indexes, historical versions), §15.1, §18.
> A pull request that breaks a rule must update this document and add an ADR.

---

## 1. Identifiers

| Rule | Detail |
|---|---|
| Primary keys | `id uuid PRIMARY KEY` on every non-join table (§14.1 "non-sequential identifiers usable publicly such as UUID") |
| Version | **UUID v7** (time-ordered → better B-tree locality than v4). Generated by Prisma (`@default(uuid(7))`) where supported, with a DB default as fallback for raw SQL and imports. Verify support at setup (TQ-22, ADR-005) |
| Join tables | Composite primary key of the two FKs (`PRIMARY KEY (organization_id, service_id)`), no surrogate id, **unless** the join row has its own lifecycle (e.g. `organization_members`, `event_registrations`, `benchmark_set_members` have ids) |
| Public URLs | Use **slugs** for SEO entities (companies, categories, cities, news, events, profiles) and UUIDs for everything else. Never expose sequential numbers |
| Exception | `invoices.invoice_number`: a legally required sequential number, kept **in addition to** the UUID |
| External references | Store provider ids in explicit columns (`provider_payment_ref`, `source_record_id`), never as PKs |

## 2. Naming

| Object | Convention | Example |
|---|---|---|
| Schema | `app` | |
| Table | `snake_case`, **plural** | `organization_members` |
| Join table | `<owner>_<related plural>` | `company_project_services` |
| Column | `snake_case` | `verification_expires_at` |
| FK column | `<referenced singular>_id`; role-prefixed when ambiguous | `organization_id`, `subject_organization_id`, `merged_into_organization_id` |
| Boolean | `is_` / `has_` prefix | `is_public`, `is_current` |
| Timestamp | `_at` suffix (`timestamptz`) | `published_at` |
| Date (no time) | `_on` or `_date` suffix (`date`) | `expires_on`, `start_date` |
| Money | `_minor` suffix (integer halalas) + `currency` | `total_minor` |
| Bilingual text | `_ar` / `_en` suffix pairs | `name_ar`, `name_en` |
| Enum type (SQL) | `snake_case` singular | `organization_status` |
| Enum type (Prisma) | `PascalCase` | `OrganizationStatus` |
| Enum values | `UPPER_SNAKE_CASE` | `UNDER_VERIFICATION` |
| Index | `ix_<table>__<columns>` | `ix_verifications__status_type_due_at` |
| Unique | `uq_<table>__<columns>` | `uq_organization_members__organization_id_user_id` |
| Check | `ck_<table>__<rule>` | `ck_point_ledger__amount_not_zero` |
| FK constraint | `fk_<table>__<column>` | `fk_company_projects__organization_id` |
| Prisma model | `PascalCase` **singular**, mapped with `@@map("plural_table")`; fields `camelCase` mapped with `@map("snake_case")` | `model OrganizationMember { … @@map("organization_members") }` |

## 3. Timestamps

| Rule | Detail |
|---|---|
| Type | Always `timestamptz`, stored in **UTC** (§14.1). Display in the user's timezone (`users.timezone`, default `Asia/Riyadh`) |
| `created_at` | `NOT NULL DEFAULT now()` on every table |
| `updated_at` | `NOT NULL`, maintained by Prisma `@updatedAt`, on every **mutable** table. Omitted on append-only tables |
| Business timestamps | A column per meaningful event (`submitted_at`, `decided_at`, `published_at`, `attended_at`) instead of inferring from `updated_at` |
| Business dates | `date` for calendar facts without time (credential expiry, project dates, periods) |
| Occurrence vs recording | Where they differ, keep both (`point_ledger.occurred_at` vs `created_at`; `analytics_events.occurred_at` vs `received_at`) |
| Windows | Daily/weekly windows computed in `Asia/Riyadh` (points caps), documented per use |

## 4. Audit fields

| Rule | Detail |
|---|---|
| `created_by` / `updated_by` | `uuid NULL REFERENCES users(id)` on tables marked **[sensitive]** in `database-entities.md` (§14.1). `NULL` = system |
| Decision fields | Entities with decisions carry their own `decided_by`, `decided_at`, `reason` (verification decisions, merges, appeals) |
| Full history | **Not** stored via triggers on every table. History lives in (a) `audit_logs` for security-relevant changes and (b) purpose-built history tables where the business needs it (`verification_decisions`, `level_assignments`, `point_ledger`, `visibility_snapshots`) |

## 5. Soft delete and archival

**Default: no soft delete.** Use it only where the PRD justifies it (§14.1 "logical deletion **for operational entities** with a retention policy").

| Strategy | When | Tables |
|---|---|---|
| **Business status** (preferred) | The PRD defines an archive state | `organizations` (ARCHIVED), `company_projects` (ARCHIVED), `opportunities` (ARCHIVED), `events` (ARCHIVED), `content_items` (ARCHIVED) |
| **`deleted_at`** | User-facing deletion of an operational entity that must be retained or restorable, with no business archive state | `media_assets`, `documents`, `saved_lists`, `saved_searches` |
| **Anonymisation** | Personal data subject to deletion rights | `users` (DEACTIVATED) + dependent personal fields |
| **Revocation columns** | Grants and awards whose history matters | `user_platform_roles.revoked_at`, `member_permission_grants.revoked_at`, `badge_awards.revoked_at`, `entitlements.revoked_at`, `benchmark_set_members.removed_at` |
| **Never deleted** | Append-only facts | `audit_logs`, `point_ledger`, `consents`, `verification_decisions`, `data_exports`, `analytics_events` (partition drop at retention end only) |
| **Hard delete** | Join rows replaced as a set; drafts never submitted; technical rows | `organization_services`, `profile_skills`, …; DRAFT projects; processed `outbox_events`; expired `idempotency_records` |

Soft-delete implementation rules:
- Unique constraints on soft-deletable tables are **partial**: `… WHERE deleted_at IS NULL`.
- Reads exclude deleted rows **explicitly in repositories** (a repository base method), not through a global Prisma extension that hides behaviour.
- A purge job hard-deletes after the retention period (BQ-33), including storage objects.

## 6. Foreign keys

| Rule | Detail |
|---|---|
| Always declare FKs | Every `*_id` column that references an app table has a FK constraint, **except** columns documented as intentionally unconstrained (`audit_logs.entity_id`, `outbox_events.aggregate_id`, `analytics_events.*`) |
| No polymorphic `(type, id)` pairs | Use one nullable FK per target + `CHECK (num_nonnulls(...) = 1)` (see `verifications`, `abuse_reports`, `appeals`, `point_ledger`) |
| `ON DELETE` | Default **`RESTRICT`**. `CASCADE` only for pure child rows that have no meaning without the parent **and** whose parent is hard-deletable (join tables, `import_rows` → `import_batches`, `notification_deliveries` → `notifications`). Never cascade from `users` or `organizations` |
| `ON UPDATE` | Not used (UUIDs don't change) |
| Cross-schema FKs | **Not allowed** (no FK to `auth.users`, ADR-003) |
| Index every FK | Every FK column is the leading column of at least one index (Postgres doesn't index FKs automatically) |

## 7. Indexes

| Rule | Detail |
|---|---|
| Every index has a reason | Written in `database-entities.md` (§14.1 "indexes for search, joining and duplicate prevention") |
| Tenant access | Composite indexes lead with the tenant/owner column: `(organization_id, status)` |
| Queues | `(status, due_at)` / `(status, available_at)` for workers and review queues |
| Partial indexes | For "active" subsets: `WHERE revoked_at IS NULL`, `WHERE status IN (…)`, `WHERE is_current` |
| Text search | GIN on `tsvector`; GIN `gin_trgm_ops` for fuzzy matching; only on `search_documents` and duplicate-detection columns |
| Arrays | GIN on filter arrays in `search_documents` |
| JSONB | No GIN on JSONB by default. Add only for a proven query |
| Review | `pg_stat_statements` + `EXPLAIN ANALYZE` for new list endpoints; remove unused indexes quarterly |

## 8. Unique constraints

| Rule | Detail |
|---|---|
| Business uniqueness in the DB | Never rely only on application checks (§20.2 duplicates, double subscriptions, repeated points) |
| Case-insensitive | `citext` for emails, slugs, domains, coupon codes |
| Normalised values | Store a normalised form for matching (`commercial_registration_number` digits only, `website_domain` lower-case registrable domain) |
| Partial uniqueness for state | e.g. one live subscription per subscriber; one open claim per claimant; one current visibility snapshot |
| Idempotency | `UNIQUE` keys for exactly-once effects: `point_ledger.idempotency_key`, `payment_provider_events (provider, provider_event_id)`, `idempotency_records (scope_key, idempotency_key)` |
| Prisma | Partial and expression unique indexes are written in migration SQL; Prisma then treats them as plain indexes. Handle `P2002` (unique violation) as a domain error |

## 9. Check constraints

Use CHECKs for invariants that are true regardless of workflow:

- value ranges (`completion_score BETWEEN 0 AND 100`, `points_score BETWEEN 0 AND 50`, `rating BETWEEN 1 AND 5`)
- "exactly one of" subjects (`num_nonnulls(...) = 1`)
- "at least one of" bilingual required fields (`num_nonnulls(name_ar, name_en) >= 1`)
- date ordering (`end_date >= start_date`)
- state-dependent requireds (`status <> 'CLOSED' OR outcome IS NOT NULL`)
- ledger integrity (`amount <> 0`, reversal ⇔ `reverses_entry_id`)

State **transitions** are enforced in domain services, not in CHECKs.

## 10. Enums

| Use a PostgreSQL enum when | Use a lookup table or text code when |
|---|---|
| Values are defined by the PRD or code **and** drive logic (statuses, roles, types) | Values are managed by staff without a deploy (categories, services, locations, skills, legal entity types BQ-21, size ranges, plan feature keys, notification types) |
| Changes are rare and go with code changes | Values need bilingual labels or ordering in data |

Rules:
- Adding a value = a migration (`ALTER TYPE … ADD VALUE`). **Never remove or rename** an enum value in place; deprecate it and migrate data first.
- Every enum is listed in `enums-and-statuses.md` with its tag (PRD-defined / derived / proposed).
- Clients must tolerate unknown enum values (forward compatibility).

## 11. JSON fields

JSONB is allowed **only** for:

| Allowed use | Examples |
|---|---|
| Structure genuinely varies or is not yet specified, and it is never joined or filtered relationally | `organizations.capacity` (RG), `events.agenda` (RG-01), survey `answers` (RG-05) |
| Snapshots frozen at a point in time | `invoices.buyer_snapshot`, `visibility_snapshots.components`, `reports.rule_versions` |
| Raw external payloads | `payment_provider_events.payload`, `import_rows.raw_data` |
| Event payloads and property bags | `outbox_events.payload`, `analytics_events.properties`, `notifications.payload` |
| Settings maps validated by schema | `organizations.field_visibility`, `profiles.section_visibility` |

Rules: every JSONB column has a **zod schema** in the owning module, validated on write; a `DEFAULT` (`'{}'` or `'[]'`) and `NOT NULL`; no business-critical relationships inside JSON. When a JSON field becomes filterable or relational (e.g. capacity ranges once BQ-21 is decided), promote it to columns or tables.

## 12. Nullability

| Rule | Detail |
|---|---|
| `NOT NULL` by default | A column is nullable only when "unknown / not applicable" is a real state |
| Meaningful NULLs | `NULL` timestamps mean "hasn't happened" (`published_at`); `NULL` FK means "no relationship" (documented) |
| No sentinel values | No empty strings, `0` or `'1970-01-01'` meaning "unknown" |
| Booleans | Always `NOT NULL` with a default |
| Arrays / JSONB | `NOT NULL DEFAULT '{}'` / `'[]'` |
| Bilingual pairs | Both nullable individually + CHECK that at least one is set when required |

## 13. Money, numbers, text

| Rule | Detail |
|---|---|
| Money | `integer` minor units (halalas) + `char(3) currency` (default `SAR`). No floats. VAT rate `numeric(5,4)` (ADR-020) |
| Scores | `smallint` for bounded integer scores; `numeric(5,2)` for weighted scores |
| Coordinates | `numeric(9,6)` |
| Text | `text` + application-level length limits (no `varchar(n)` in the DB), except `char(2)`/`char(3)` codes |
| Bilingual | Paired `_ar`/`_en` columns for the fixed two languages (§17 AR/EN; ADR-021) |
| Arabic search normalisation | Done in a SQL function `app.normalize_ar(text)` + the same logic in `common/text` for query input; the two implementations are covered by shared test fixtures |

## 14. Transactions and concurrency

| Rule | Detail |
|---|---|
| Boundaries | One application-service use case = one transaction. Catalog in `transaction-boundaries.md` |
| Propagation | `TransactionRunner` (AsyncLocalStorage) so audit, outbox and ports join the same transaction without passing `tx` manually through every layer |
| Isolation | `READ COMMITTED` (Postgres default) + **explicit row locks** (`SELECT … FOR UPDATE`) for check-then-act invariants (capacity, caps, last owner, coupon limits, benchmark changes). `SERIALIZABLE` only where a lock cannot express the invariant (none identified yet) |
| Lock order | Lock parents before children and lower ids before higher ids to avoid deadlocks (e.g. merge: lock both organizations ordered by id) |
| Duration | No network calls (payment gateway, Supabase admin, SMS) **inside** a DB transaction. Call before (with an idempotency key) or after (via outbox) |
| Retries | Retry serialization and deadlock errors (`40001`, `40P01`) up to 3 times at the TransactionRunner level |
| Optimistic concurrency | For long-lived edit forms (organization profile), accept `If-Match` / `version` to prevent lost updates (optional, Phase 1 candidate) |
| Timeouts | `statement_timeout` for the app role (e.g. 15 s API, longer for worker sessions) |

## 15. Data classification tagging

Every table in `database-entities.md` carries its dominant class (§18.1). Column-level exceptions (e.g. `users.email` = Personal, `organizations.commercial_registration_number` = Public or Confidential per ORG-10 setting) are noted in the data dictionary (Phase 0 deliverable, §6). Personal and Confidential columns:
- are excluded from `search_documents` and public DTOs;
- are masked in logs and audit `changes`;
- are covered by the retention and anonymisation jobs.
